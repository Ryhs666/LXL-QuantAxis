# ADR-0003：采用 Point-in-Time 数据语义

- 状态：Accepted
- 日期：2026-08-03
- 决策负责人：LXL-QuantAxis Architecture
- 适用范围：行情、财务、新闻、另类数据、因子、回测和 AI 研究

## 背景

专业投资研究必须区分“事件发生时间”和“研究者可获得数据的时间”。财报对应报告期，但可能数月后才发布并继续修订；新闻有事件时间、发布时间和抓取时间；行情也存在停牌、公司行动和供应商修订。仅按日期查询当前最新值会把未来信息带入历史研究。

## 决策

所有时间敏感数据采用 Point-in-Time 语义，至少记录：

- `event_time`：经济或市场事件实际发生时间。
- `available_at`：该数据首次可被策略合法使用的时间。
- `ingested_at`：系统收到该版本的时间。
- `revision_id`：供应商修订版本。
- `provider`：来源。
- `quality_flags`：完整性、异常和许可标记。

研究查询必须提供 `as_of`，并且只能返回 `available_at <= as_of` 的版本。修订数据追加保存，不能覆盖历史版本。

## Dataset Snapshot

每次回测和 AI 研究关联不可变 `DatasetSnapshot`，其 Manifest 包含数据集版本、覆盖范围、内容 Hash、质量结果、Provider 和生成时间。`ResearchRun` 同时记录策略版本、代码 Commit、配置、随机种子、成本模型和环境指纹。

## 市场时钟

- 数据可得时间与信号时间分离。
- 默认日线收盘信号最早在下一可交易时点执行。
- 时区和交易日历属于数据契约，不由调用方自行猜测。
- 缺失或陈旧价格采用显式 stale policy，不能静默前向填充后继续交易。

## 结果

### 正面影响

- 防止财务、新闻和修订数据的未来泄漏。
- 历史研究和 AI 报告可复现、可审计。
- 因子衰减、样本外验证和策略比较具有统一时间语义。

### 代价

- 存储量增加，需要保留数据版本和 Manifest。
- Provider Adapter 必须补齐时间和修订元数据。
- 旧缓存数据可能只能标为低可信度，不能自动假定 PIT 完整。

## 验收原则

- 历史日期查询永远不能返回当时尚未发布的数据版本。
- 修订不会改变旧 Dataset Snapshot 的 Hash。
- 相同 Research Run Manifest 产生相同结果。
- PIT 违规检查是回测和策略 Promotion 的阻断门。

## 备选方案

- 只保存最新值：拒绝。无法进行可信历史研究。
- 由每个策略自行 `shift(1)`：拒绝。无法覆盖财务发布、新闻和修订语义。
- 依赖供应商声明“无未来数据”：拒绝。系统仍需自己的可验证边界。
